GUIDES / HTML-FIRST

Build with less machinery.

Install Syntyr, integrate it into the renderer you already use, and progressively enhance only where interaction is required. These quick references link to complete source guides.

InstallationIntegrations CustomizationProgressive enhancement PerformanceAccessibility

01 / Install once, own your markup

Start with syntyr.core.css from a pinned release, self-host it, and apply syn-root to the area Syntyr owns. You don't need npm or a build plugin in the consuming application.

<link rel="stylesheet" href="/css/syntyr.core.css">
<main class="syn-root" data-syn-theme="studio">
  <button class="syn-button syn-button--primary">Continue</button>
</main>

02 / Any HTML renderer

Syntyr is a presentation layer, not a request client or state manager. Use the same markup with HTMX, Django templates, Go templ, Astro, React, Vue, Svelte or Rails. Native controls work without client-side code; your application owns submission, state and data.

For HTMX and similar tools, keep CSS classes on persistent elements, use native forms, and apply data-syn-semantic to opt-in elements that receive transient framework classes.

03 / Themes and design tokens

Change visual identity through data-syn-theme on a component subtree. Studio, Grid and Noir are part of the published alpha.4 release; the unreleased alpha.5 source adds four more palettes. Override exposed --syn-* custom properties locally rather than editing generated CSS.

Interactive theme editor · Complete token reference (Markdown)

04 / Progressive enhancement

Use <details> for disclosures and real anchors for navigation. Native popover and dialog invoker commands only work in supporting browsers; supply a working fallback or progressive JavaScript enhancement when an interaction is essential. CSS effects should never be required for content or workflow completion.

Browser compatibility and fallbacks (Markdown) · Native HTML demo

05 / Performance without arbitrary budgets

Load only the CSS modules you use; prefer the core stylesheet for ordinary apps. Decorative effects and geometry are separate opt-ins. Avoid unnecessary layout shifts, audit real pages in representative browsers, and measure transferred CSS, rendering and interactions rather than enforcing arbitrary bundle-size ceilings.

Performance guidance (Markdown) · Validation methodology (Markdown)

06 / Accessible by default, verified in context

Keep visible labels, meaningful native semantics and keyboard focus. Validate contrast across all active themes, check mobile reflow at 320px, and inspect forced-colors and reduced-motion modes. CSS alone cannot guarantee accessibility in an application with poor markup.
