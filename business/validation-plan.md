# Syntyr: 30-day validation and 90-day release gates

## Days 1–7: polished free proof

- Finish the MIT public API and original Grid/Noir demos. Keep all free examples usable without login.
- Run Chromium, Firefox and WebKit checks; manual accessibility, keyboard, 200%/400% zoom, contrast and focus checks.
- Publish reproducible size report for core/semantic/effects, zero JS runtime and externally fetched assets.
- Check provisional `Syntyr` name for naming/trademark conflicts before marketing at scale.
- Invite 10 developers building Go/HTMX/Astro/static marketing sites to critique real markup and portability.

## Days 8–14: sell value, not components

- Make a **paid-kit concept** using screenshots and a video/walkthrough; clearly say `preorder` if it is not built.
- Test $59 Console Kit and $149 Studio bundle on a landing page with an actual checkout or explicit buy intent.
- Track qualified visitors, live-demo engagement, checkout starts, completed orders, refunds, and customer support cost.
- Do not charge for a product without clear delivery commitments and lawful refund terms.

## Days 15–30: delivery threshold

- Target 10 paid kit orders/preorders or equivalent signed design-partner commitments before building extensive premium inventory.
- Produce a useful 6–10-screen kit with mobile, empty/error, form validation, keyboard-first navigation and documentation.
- Offer 2–3 targeted custom-integration engagements with scoped contracts to discover real friction points.

## Days 31–90: decision gate

- Double down only if buyers use templates in real deployed products, not if only GitHub stars rise.
- If 50+ qualified prospects view the paid demo but fewer than 2 buy, reconsider differentiation and price.
- Raise the paid bundle price only after repeated purchase/use evidence; don't chase a vanity roadmap.
- Consider a hosted theme generator or subscription only if repeat usage and demand for hosted services is demonstrated.

## Reporting dashboard

Weekly: qualified visits → kit-page visits → checkout starts → purchases; gross revenue, refunds, payment fees, owner hours, support tickets, referral source, and repeat customer feedback. Report contribution after time and cash cost, not just gross revenue.

## No-go criteria

No legally clear commercial assets; inability to confirm source ownership/license; unresolved accessibility blockers; recurring support burden greater than purchase value; or no credible buyer interest after repeated direct conversations. In those cases the MIT core can still succeed as a marketing/credibility asset, but should not absorb unlimited engineering time.
